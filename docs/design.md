# 設計の提案

v0.1.0 の時点の提案。実機(iPhone SE 第2世代)で確かめていないものは「見込み」と書く。データの URL・形式・量は [data-sources.md](data-sources.md)。

## 1. 共通の土台: 見る位置と向き(ScopeViewpoint)

カメラ表示と幽体離脱で、重ねる情報の計算を1つにする。

```
              見る位置(緯度・経度・目の高さ) + 向き(CameraAttitude) + 画角(tangents)
                                   = ScopeViewpoint
                                          |
         +--------------------------------+--------------------------------+
         |                                                                 |
   カメラ表示(v0.1〜)                                               幽体離脱(v0.4〜)
   位置: GPS、目の高さ: 地面の標高+手の高さ                          位置: 地図で選んだ点、目の高さ: その地面+1.6m(歩く)/自由
   向き: CoreMotion(+方角の補正)                                    向き: 指の操作で作る(CameraAttitude.looking)
   画角: カメラの videoFieldOfView                                   画角: 同じ式(既定はカメラと同じ値)
   背景: カメラの映像                                                背景: 地形・航空写真・建物の立体
         |                                                                 |
         +------------------ 同じ Canvas の重ね描き(ScopeOverlay) ----------+
                   印: ScopeViewpoint.targets(marks) → point(bearing:elevation:)
                   面: ScopeViewpoint.point(latitude:longitude:altitude:)
```

- 方角・距離・仰角(地球の丸みと屈折を含む)・画面上の位置は、`ScopeViewpoint` だけを通す。カメラ表示と幽体離脱で別の式を書かない
- 幽体離脱の立体(地形・建物)は 3D の描画エンジンで描き、その上に重ねる情報は、カメラ表示と同じ 2D の Canvas で描く。3D のカメラの画角と向きは `ScopeViewpoint` から作る(同じ値から作るので、立体と印がずれない)
- テスト: 「地上の点をカメラ表示の式で投影した位置」と「幽体離脱の 3D のカメラで投影した位置」が1pt以内で一致することを、ユニットテストで確かめる(3D のエンジンの投影の式を純粋な関数に書き出して比べる)
- 重ねる情報は、すべて `ScopeMark`(点)か、次の「面」(浸水の水面など)の形にそろえる

## 2. カメラ表示に重ねるもの

| 重ねるもの | 描き方 | データ | 通信 |
|---|---|---|---|
| 避難場所の方角と距離 | 地点と同じ印。災害の種類で絞る(今の災害に合う所だけ)。近い順に5件を強く、残りは薄く | 指定緊急避難場所(種類ごとのフラグ)、指定避難所 | 保存した分だけで計算(圏外でも使える) |
| 浸水の深さ(洪水・津波・高潮) | 半透明の水面。格子の点ごとに「地面の標高+想定の深さ」の高さに面を張る | ハザードのタイル(色→深さの区間)、標高タイル | Wi-Fi で保存 |
| 土砂災害の区域 | 地面に沿った半透明の塗り(黄・赤) | 土砂災害警戒区域のタイル | Wi-Fi で保存 |
| 震源 | 地平線の下に、深さの分だけ下げた印(仰角 = −atan(深さ÷距離))と、M・時刻 | 気象庁の地震情報 / P2P地震情報 | 一覧は数KB |
| 震度の分布 | 観測点の印を、震度の色の小さな点で地面に置く(遠いものは方角の帯) | 地震の詳細の観測点の震度 | 1件数十KB |
| 津波警報の沿岸 | 警報の出ている予報区の沿岸の方角に、予想の高さの柱(「予想 3m」)。帯で方角の範囲 | 津波予報(予報区の名前と高さ)+予報区の代表点(同梱) | 数KB |
| 今いる場所の標高との比べ | 画面の下に「ここの標高 4.2m / 想定の浸水 0.5〜3m / 津波の予想 3m」。水面の高さが目の高さを超えるときは、画面の上の端から水面を描く | 標高API、標高タイル | 70B |

### 浸水の水面の作り方

1. 現在地のまわり(半径 300m〜1km)を、10〜20m の格子に切る
2. 格子の点ごとに、ハザードのタイルの画素の色から深さの区間を引く(凡例の色と一致する色だけ。境目のなじんだ色は捨てる)
3. 標高タイル(dem5a、5m)で地面の高さを引き、水面の高さ = 地面の高さ + 深さ。深さは区間の**上の値**で描き、文字で区間を出す(「0.5〜3m」)
4. 隣どうしの点で四角を作り、`ScopeViewpoint.point(latitude:longitude:altitude:)` で画面の位置にして、遠いものから半透明で塗る(Canvas の Path)
5. 計算は位置が 20m 以上動いたときだけ、メインスレッドの外で行う。描くのは見えている向きの四角だけ(SE2 で 30fps を保つため、四角の数の上限を 2,000 程度にする見込み)

## 3. 「想定」であることの示し方

- 水面・区域・津波の柱には、必ず「想定」「予想」の文字を付ける。色は凡例の色に合わせるが、**斜めの縞(ハッチング)を重ね、実際の水と見分けられるようにする**
- 画面の上に常に帯を出す: 「洪水の想定(想定最大規模)」「出典: 国土地理院 重ねるハザードマップ(各自治体の想定)」。帯をタップすると、想定の条件(想定最大規模の降雨、L2 の津波など)と、データの更新日を出す
- 深さは区間で出す(「0.5〜3m」)。1つの数にしない(色から読める精度がそれだけなので)
- 区域の外は「浸水の想定なし」ではなく、「この範囲では想定の区域に入っていない(想定を超える災害はある)」と書く
- 津波の予想の高さは「沿岸での予想の高さ」と書き、内陸の水面としては描かない(津波は沿岸の柱と方角だけ。浸水の範囲は津波浸水想定のタイルで別に描く)
- 地震・津波の情報は「◯分前の情報」と、元の発表元(気象庁)を出す。P2P地震情報経由のものは、そう書く

## 4. 幽体離脱モード

カメラを使わず、地図で選んだ場所に立ったつもりで、地形・航空写真・建物を立体で描き、その上に同じ情報を重ねる。旅行先や実家などを前もって確かめるためにも使う。

- 視点: 歩く目線(地面+1.6m。指で向きを変え、長押しで前へ歩く)と、自由に飛ぶ視点(高さを変えられる)を切り替える
- どちらも、立っている点と向きから `ScopeViewpoint` を作り、重ねる情報はカメラ表示と同じ計算で描く
- データ: 選んだ点のまわりを、Wi-Fi のときに前もって保存する(半径 1km・3km・5km から選ぶ)。保存したエリアは一覧にして、消せる

### 描き方の比較

| | SceneKit | RealityKit(ARView の nonAR) | Metal(自前) |
|---|---|---|---|
| iOS 17 で使えるか | 使える | 使える(`ARView(cameraMode: .nonAR)`、`MeshResource.generate(from:)` は iOS 15〜) | 使える |
| 地形のメッシュ・テクスチャ | `SCNGeometry` に頂点・UV・航空写真を渡すだけ | `MeshDescriptor` + `UnlitMaterial`(航空写真は影が焼き込まれているので、光の計算はいらない) | 全部自分で書く(シェーダー、テクスチャの読み込み、深度) |
| 重さ(SE2 の見込み) | 軽い。描画の手順が少なく、メモリも少ない | 既定では後処理(ブルーム、AO、被写界深度など)があるので、`renderOptions` で全部切る。切れば SceneKit と同程度の見込み | 一番軽くできるが、軽くするのも自分の仕事 |
| これから | 2025 年に Apple が非推奨(新しい機能は足さない)にした。iOS 26 でも動くが、先は短い | Apple が今後の 3D の中心にしている | 変わらない |
| Windows で開発する手間 | 少ない | 少ない | 多い(シェーダーの誤りを実機なしで探すのが難しい) |
| 2D の重ね描きとの合わせ | `SCNCamera` の画角と向きを `ScopeViewpoint` から入れる | `PerspectiveCamera` の画角と向きを `ScopeViewpoint` から入れる | 投影の行列を自分で作るので、一番合わせやすい |

**提案: RealityKit(ARView の nonAR、`UnlitMaterial`、後処理を全部切る)**。理由は、SceneKit が非推奨になり先が短いこと、Metal は実機なしで作るには手間が大きすぎること。描くものは「地形+航空写真+建物の箱」だけで、光の計算をしない(Unlit)ので、A13 で 30fps は届く見込み。v0.4 の最初に、SE2 で 3km 分の地形を出して fps を測ってもらい、30fps を切るなら SceneKit に切り替える(描画の部分は `GhostRenderer` のプロトコルの裏に置き、差し替えられるようにする)。

### メッシュの作り方(SE2 向けの量の目安)

- 地形: 距離で細かさを変える。〜1km は標高 5m(dem5a、z15)を 1 タイル 64×64 の格子に間引く、1〜3km は 10m(dem、z14)を 32×32、3〜5km は z13 を 16×16
- 航空写真: 〜1km は z17、1〜3km は z16、3〜5km は z15
- 建物: PLATEAU のある都市は高さのある箱(LOD1)、ない所は国土地理院のベクトルタイルの形を、階数が分からないので一律の高さ(例 6m)の薄い箱にし、「高さは推定」と出す
- 三角形の数の上限を 30 万、テクスチャの合計を 64MB 程度にする見込み(SE2 のメモリ 3GB のうち、アプリが安全に使える分を考えて)

### 保存するデータの量の目安

1枚の大きさは data-sources.md の実測(東京の市街地・荒川周辺)から: 航空写真 25KB(川の上の実測 16KB から、市街地を多めに見積もった)、標高 dem5a z15 50KB(空白を埋める dem_png z14 18KB を別に)、建物(提供実験のベクトルタイル z16)44KB、浸水のタイル 1層 6KB(データのある所の半分として、洪水・津波・高潮・土砂の4層)。タイルの数は、緯度 35.7° で半径 r の正方形に入る数(端を含む多めの数)。

| 半径 | 航空写真 | 標高 | 建物(3km まで) | ハザード 4層 | 合計の目安 |
|---|---|---|---|---|---|
| 1km | z17 100枚 = 2.5MB | z15 16枚 = 0.8MB | z16 36枚 = 1.6MB | 0.4MB | **約 5MB** |
| 3km | z17 100枚 + z16 160枚 = 6.5MB | z15 64枚 = 3.2MB | z16 196枚 = 8.6MB | 2.4MB | **約 21MB** |
| 5km | + z15 80枚 = 8.5MB | z15 144枚 = 7.2MB | 8.6MB(3km より先は描かない) | 5.8MB | **約 30MB** |

- これに避難場所(z10 のタイル1〜4枚分、直した後で数百KB)と、dem_png の予備が加わる
- PLATEAU の都市では、建物を「外形と高さ」に直したもの(都市ごとに前もって作る)に替える。3km 四方で数MB の見込み(未計測)
- どれも Wi-Fi のときだけ保存する。モバイル通信で幽体離脱を開いたときは、保存した範囲だけを描き、外は「保存していない範囲」と出す

## 5. SE2 の見込み

実機で測っていない。A13・メモリ 3GB・画面 375×667pt(2倍)から見積もった値。

- カメラ表示の重ね描き(Canvas): 印 50 個+水面の四角 2,000 個程度なら 30fps の見込み(スマートダッシュボードでは、SE2 と LiveContainer でカメラ表示が動き、静止していれば印がほぼずれないという報告がある(v0.8.0)。印の数を増やしたときの fps は報告がない)。水面の格子の計算は、位置が動いたときだけメインスレッドの外で行う
- 幽体離脱(RealityKit、Unlit、後処理なし): 三角形 30 万・テクスチャ 64MB までなら 30fps の見込み。半径 5km では、遠い所の格子を粗くして三角形を抑える。テクスチャは 256px の JPEG をそのまま使い(合成して大きな1枚にしない)、遠い所は z15 にする
- メモリ: 半径 5km の保存分 30MB をすべて展開すると、写真 340 枚 × 256KB(RGBA)= 約 87MB。見えている範囲と近い所だけを読み込み、離れたものは捨てる
- 電池: カメラ表示はスマートダッシュボードと同じく、開いている間だけカメラ・GPS・モーションを動かす。幽体離脱はセンサーを使わない(GPS も止める)
- v0.4 の最初に、SE2 で fps とメモリを測る画面(開発者向け)を作り、利用者に測ってもらう
